# 裝工具：新電腦、檢查工具說 MISSING → 你來裝，主人只按允許與登入

> 主人說「幫我裝工具」「繼續裝工具」「新電腦要準備」「檢查工具說 MISSING」就是這本。你（AI 夥伴）照這本一項一項裝。主人只做三種事：電腦問「是否允許」時按「是」、在瀏覽器登入、聽你說明要同意哪些條款後說好。人看的說明在 `先看這裡.html`；指令以這本為準。

## 要裝的五樣（每一樣是做什麼的，裝之前用這一句跟主人說）

| 工具 | 一句話 | 一定要嗎 |
|---|---|---|
| Git | 記下資料夾每一版的樣子，改壞了能回到前一版 | 要 |
| GitHub CLI（指令叫 `gh`） | 讓你替主人把資料夾存到他自己的 GitHub、從 GitHub 抓回來 | 要 |
| Node.js | gws 靠它安裝；主人不會直接用到 | 要用 gws 才要 |
| gws | Google Workspace 的指令工具：讓你找信、讀信、把回信建成 Gmail 草稿、讀雲端硬碟 | 選配（見下面〈gws〉） |
| uv | 幫你跑小程式（組信用的那支）；不用另外裝 Python | 要用 gws 寫信才要 |

## 停手

- **一項一個「好」**：每一項開始前說一句：要裝什麼、會跳出什麼視窗、大概多久。他對**這一項**說好再跑；一個「好」不代表後面全部。
- **只裝這本列的，用這本的指令。** 指令失敗不要換來源、不要改去別的網站下載安裝檔；停下來，把畫面最後幾行原樣給他看。
- **winget 的條款**（Windows）：第一次用 winget 前，先跟他說「會同意微軟 winget 的來源條款，和這次要裝的套件授權」，他說好才在指令後面加 `--accept-source-agreements --accept-package-agreements`。
- **「是否允許」**：每次會跳視窗之前先跟他說；沒看到視窗就請他看工作列有沒有在閃的盾牌圖示。你沒說要裝東西卻跳出來，請他按「否」。跳出要**管理員帳密**、或說沒有權限 → 停，這一項記「需要資訊人員」。
- **學校管控的電腦**：沒有 winget、winget 被擋、裝不了 → 停，記「需要資訊人員」，請他把 `先看這裡.html` 轉給資訊人員。
- **前一項沒裝好，靠它的就不做**：Git 沒好就不碰 GitHub；Node.js 沒好就不裝 gws。
- **跑很久不等於失敗**：第一次都要下載，網路慢可以到 10 分鐘以上。逾時或沒有新輸出時，**不要馬上重跑安裝**（Windows 一次只能跑一個安裝程式）：先跑一次檢查工具，看裝好了沒。
- **不改電腦設定**：不跑 `Set-ExecutionPolicy`、不改防毒、不改系統環境變數。Windows 的 PowerShell 一律打 `npm.cmd`、`gws.cmd`，不打 `npm`、`gws`。
- **登入和選項都是他的事**：Google、GitHub 在瀏覽器登入由他按。帳號、密碼、驗證碼不要替他輸入，也不要叫他貼給你。
- **你的權限擋住**（沙盒、唯讀、指令被拒）→ 照實說被擋的是哪一行，由他決定要不要允許。不要叫他把權限整個打開。
- **不推回陳老師的 repo**：這個資料夾是從陳老師的 GitHub 抓來的，就要先鎖住（下面〈先鎖住〉）。鎖不上就停，任何 git 的寫入都不做。

## 先看是哪種電腦

- Windows → 照〈Windows〉。
- Mac → 照〈Mac〉。打 `uname -m`：`arm64` 是 Apple 晶片，`x86_64` 是 Intel；裝之前把結果告訴他。

## 先鎖住（資料夾裡有 `.git` 才做）

還沒有 Git 就先裝 Git（Windows 第 1 步、Mac 第 1 步），裝好回來做這一段。鎖之前跟他說一句：「我先把這個資料夾鎖住，之後寫的東西不會推回陳老師那邊。」然後打 `git remote -v`。找網址有 `cwstedctw` 的那一個（剛抓下來時叫 `origin`；做過 `存到我的GitHub.md` 之後叫 `upstream`）：它 push 那一行還不是 `no_push`，就跑 `git remote set-url --push <那個名字> no_push`，再打一次 `git remote -v` 確認。網址是他自己帳號的那一個不要鎖。

## Windows

**跑檢查工具**：在資料夾根目錄，PowerShell 打 `.\檢查工具.cmd --no-pause`，Git Bash 打 `./檢查工具.cmd --no-pause`。畫面是英文：OK＝有了，MISSING＝一定要但還沒裝，`--`＝選配或還沒做。

**第一輪：裝程式（Git、Node.js、GitHub CLI 會跳「是否允許」）**

0. 跑檢查工具。一定要的只有 git、gh：這兩樣 MISSING 就往下裝，已經 OK 的跳過。node、uv、gws 是選配（顯示 `--`），他說要用 gws 才裝。
1. Git：`winget install --id Git.Git -e --source winget`
2. GitHub CLI：`winget install --id GitHub.cli -e --source winget`
3. Node.js（要用 gws 才裝）：`winget install --id OpenJS.NodeJS.LTS -e --source winget`
4. uv（要用 gws 寫信才裝；不用管理員權限）：`winget install --id astral-sh.uv -e --source winget`
5. 在 `memory/log.md` 檔尾記一行「裝工具第一輪：裝好哪些、哪些卡住、他說不裝哪些」。然後請他把 AI 程式**整個結束**再打開（只按右上角 ✕ 不一定算結束，最保險是重新開機），打開同一個資料夾，貼「請讀 AGENTS.md 報到，然後繼續裝工具」。新裝的程式要重開才叫得到。

**第二輪：重開之後**

6. 確認報到印的路徑是同一個資料夾，讀 log 最後一行接著做；再跑一次檢查工具。還是叫不到 → 請他重新開機一次；不要自己改路徑設定。
7. Git 第一次用要報名字（已經設過就跳過；`git config --global user.name` 有印東西就是設過）：先跟他說「Git 每存一版會記是誰存的，所以要一個名字和信箱；用英文名或暱稱就可以。之後把這個資料夾存到 GitHub 時，我會改用 GitHub 給的隱藏信箱，真的信箱不會出現在紀錄裡」，再問他要用什麼，`git config --global user.name "<名字>"`、`git config --global user.email "<信箱>"`。
8. GitHub 登入：`gh auth status` 已經顯示登入 → 把帳號念給他確認就好。還沒 → `gh auth login --web --git-protocol https`，它印出的一次性八碼念給他，請他在瀏覽器貼上、登入、按授權。登入後打 `gh api user --jq .login`，把帳號念給他，確認是他的。
9. gws（他說要才做）：見下面〈gws〉。
10. 最後跑一次檢查工具，把結果整段貼給他看；在 log 記一行「裝工具完成：OK 幾項；卡住哪幾項、原因」。

## Mac

**跑檢查工具**：在資料夾根目錄打 `bash 檢查工具.command --no-pause`。

1. Git：打 `git --version`。Mac 沒裝過會跳出「要安裝命令列開發者工具嗎」→ 請他按「安裝」，等它裝完（幾分鐘到十幾分鐘）再打一次。
2. Homebrew（Mac 上裝工具的管理程式）：打 `brew --version`。有 → 用它裝下面幾樣。沒有 → **不要自己裝 Homebrew**（要他的電腦密碼）；改用下面每一項的「沒有 brew」做法。
3. GitHub CLI：有 brew → `brew install gh`。沒有 brew → 請他到 `https://cli.github.com` 按下載，選 macOS 的 `.pkg` 安裝檔（Apple 晶片選 arm64，Intel 選 amd64），雙擊安裝。
4. Node.js（要用 gws 才裝）：有 brew → `brew install node`。沒有 brew → 請他到 `https://nodejs.org` 下載 LTS 版的 macOS 安裝檔，雙擊安裝。
5. uv（要用 gws 寫信才裝）：有 brew → `brew install uv`。沒有 brew → 先跟他說「這一行會從 uv 官方網站下載安裝程式並執行」，他說好才跑 `curl -LsSf https://astral.sh/uv/install.sh | sh`。
6. 在 `memory/log.md` 檔尾記一行「裝工具第一輪（Mac）：裝好哪些、哪些卡住、他說不裝哪些」，再請他把 AI 程式整個結束（按 Command+Q）再打開，貼「請讀 AGENTS.md 報到，然後繼續裝工具」。
7. 重開後照 Windows 第 6 到 10 步做（檢查工具改跑 `bash 檢查工具.command --no-pause`）；Mac 上指令是 `npm`、`gws`，不用加 `.cmd`。

## gws（選配；他說要讓你處理信箱與雲端硬碟才做）

先跟他說清楚兩件事：

- **不裝 gws 也能用**：ChatGPT 與 Claude 桌面版自己就能接 Gmail、Google 雲端硬碟（在設定裡的「連接器」或「應用程式」，他自己按連接）。只是找信、讀信、整理重點的話，那條路比較簡單。gws 多的是：把回信建成 Gmail 草稿並帶附件、整批處理。
- **gws 要一個登入設定檔 `client_secret.json`**，不是裝好就能登入。這個檔要從 Google Cloud 做出來，由發這個資料夾給他的人（老師、陳老師或單位的資訊人員）提供。沒有這個檔就先停在「裝好、還沒登入」，請他去問；不要用來路不明的檔。

步驟：

0. 還沒有 Node.js、uv 就先裝（Windows 第 3、4 步；Mac 第 4、5 步），裝完請他把 AI 程式整個結束重開，再往下。

1. 裝：Windows `npm.cmd install -g @googleworkspace/cli`，裝完 `gws.cmd --version`；Mac `npm install -g @googleworkspace/cli`，裝完 `gws --version`。Mac 出現 `EACCES`（沒有權限）→ 停，照實說，不要加 `sudo`。
2. 登入設定檔：他拿到 `client_secret.json` 之後——Windows 請他把檔放進這個資料夾或「下載」資料夾，**自己雙擊 `設定信箱.cmd`**（畫面是英文；它印的 WORK Google account 指他平常工作或上課用的 Google 帳號）；Mac 請他把檔放到 `~/.config/gws/client_secret.json`（資料夾沒有就先建），然後你跑 `gws auth login -s "gmail,drive,calendar,sheets,docs"`（引號不能省），瀏覽器由他登入。
3. 驗：`gws auth status`（Windows 打 `gws.cmd`）看到 `"has_refresh_token": true`，**而且帳號是他的**（念給他聽、請他確認），才算。
4. 試一次：照 `寫信建草稿.md` 建一封寄給他自己的測試草稿，請他到 Gmail 草稿匣看到、寄件備份沒有，再請他自己把那封草稿刪掉。

`client_secret.json` 不進 git（`.gitignore` 已經擋了）。

## 驗收

- 檢查工具裡 git、gh 是 OK；GitHub CLI 有登入、帳號是他的。要用 gws 的話再加：node、uv、gws 是 OK，gws 有登入、帳號是他的。
- 他說不裝的項目記「他說不裝」，不算卡住。
- 卡住的項目寫清楚：卡在第幾步、畫面上的原文、他的電腦是不是學校管控的。請他把這段傳給發這個資料夾給他的人。
